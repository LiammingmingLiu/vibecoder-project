01 / Decisions

相对 V0.1 的五个决策

#决策理由
1前端只有对话框
不做表单和标签按钮		 需求千人千面，交给模型解析比穷举 button 更省工也更准
2画像从自然语言里长出来
不做 onboarding 问卷		 用户说完那句话，系统把解析结果反过来当他的名片给他确认。零表单，拿到结构化画像
3游戏是硬过滤
不是权重		 否则会出现「想玩三角洲却匹配到玩瓦的」，Demo 当场崩
4匹配后进入持续聊天框
不是阅后即焚		 聊天记录是后续画像的养料。Demo 里只做前端持久化
5北极星是复玩率
不是匹配成功率		 用户要的是「每晚那个固定的大哥」，不是每天一个新陌生人。Demo 不实现，但演示时要讲

02 / Flow

用户流程：两屏 + 一个聊天层

屏 1 · Onboarding（自己是谁）

一个对话框，一句提示：

先用一句话介绍下你自己，方便别人找到你。 比如：我玩三角洲和瓦，水平一般，I 人，愿意开麦但不爱指挥，一般晚上 9 点后在线。

支持文字输入，语音输入为可选加分项（见 §06）。提交后展示搭子名片——解析出的标签以 chip 呈现，可点击删改：

三角洲行动瓦罗兰特 水平普通I 人 开麦不指挥21:00 后在线

底部一个按钮：这就是我 →。允许跳过，跳过则以游客身份进入，匹配时降级为只用当次需求。

屏 2 · 匹配（想找谁）

同一个对话框，换提示语。覆盖三种真实状态，全部走自然语言，不加任何额外控件：

A不知道玩什么「随便玩点啥，有人一起就行」
B知道玩什么「今晚打三角洲」
C知道玩什么 + 对人有要求「今晚打三角洲烽火，找个佛系不骂人的，最好也是 I 人」

点击开始匹配 → 2—4 秒动画，依次展示：理解需求 → 寻找在线玩家 → 比较偏好 → 找到了。

屏 2 结果 · 搭子卡片

小北 ｜ 今晚在线 [ ▶ 听 8 秒语音 ] ← 语音占位，见 §06 三角洲行动 · 烽火地带 契合度 92% ◆ 你们都想佛系搜图，不追求极限收益 ◆ 都愿意开麦，但都不喜欢指挥压力 ◆ 今晚可玩时间高度重合 "我一般 9 点上线，混两把就睡，不卷。" [ 打个招呼 ] [ 换一个 ] 举报 / 屏蔽 · 模拟玩家 · Demo 演示数据 ·

聊天层

点「打个招呼」滑出聊天框，预填一句 AI 生成的破冰开场白，用户可改可直接发。

  • 对方 1—2 秒后有脚本化回复（2—3 轮），最后一句主动给出房间号
  • 聊天记录写入 localStorage，返回再进仍在
  • 顶部有「回到匹配」入口，可切换已有的几个会话
产品定位提醒

这个聊天框的目的是让两人 30 秒内进游戏，不是把人留在这里聊天。不要做成 IM。

03 / Logic

解析与匹配

3.1 解析

一次 LLM 调用，输入自由文本，输出结构化 JSON：

{
  "games":  ["三角洲行动"],
  "mode":   "烽火地带",
  "time":   "今晚 21:00-23:00",
  "level":  "普通",
  "goal":   "轻松娱乐",
  "mic":    "愿意开麦",
  "style":  "佛系",
  "personality": "I",
  "wants":  ["不压力", "情绪稳定"]
}

缺失字段一律填 不限，绝不阻断用户。同一次调用顺带返回破冰开场白，省一次往返，且延迟正好填满匹配动画。

这一条不是可选项

必须写本地关键词 fallback。现场网络挂了要能无缝降级，不能白屏。

3.2 匹配

第一步  硬过滤 ── 筛出玩同款游戏的候选人
        若为零，降级到全池，并显式提示
        「暂时没有完全一致的玩家，这是最接近的」

第二步  池内加权排序
        时间重合    30%
        目标与风格  25%
        开麦偏好    20%
        水平接近    15%
        性格 / MBTI 10%   ← 只做展示和破冰，权重压到最低

MBTI 和星座是社交货币，不是匹配变量。放在卡片上做话题起点，别让它主导结果。

3.3 数值约束

不定死一定穿帮：

·契合度取值锁在 68—95永不出现 100%
·「换一个」递减 92 → 87 → 83 → 79避免第二次蹦出 91% 显得随机
·在线人数每 3 秒 ±1~3 缓慢漂移固定数字看起来假

04 / Data

模拟数据规格

候选池
  • 24—30 个候选人
  • 覆盖 6—8 款热门游戏，每款至少 3 人（否则「连续换三个」必穿帮）
  • 每人字段：昵称、头像、在线时段、游戏与模式、水平、风格、开麦偏好、MBTI、一句自我介绍、2—3 轮聊天脚本
  • 语音方案若启用：共用 4—5 段预置音频，不必每人一段

05 / Stack

技术

纯前端单页，无后端。

  • 单个 HTML 文件，Tailwind CDN
  • 状态全部在内存 + localStorage
  • 唯一外部依赖是解析用的 LLM 接口，带本地 fallback

深色背景、荧光高亮、半透明卡片、大按钮、手机端可单手操作。动效只服务于反馈，不延长路径。

06 / Scope

工时拆解与砍功能优先级

按此顺序做，时间不够就从下往上砍。

优先级内容预估
P0模拟数据 + 匹配算法 + 本地关键词解析45 min
P0屏 2 匹配流程（输入 → 动画 → 卡片 → 换一个）60 min
P0视觉与响应式45 min
P1屏 1 Onboarding + 搭子名片40 min
P1聊天层 + 脚本化回复40 min
P2接真实 LLM 解析（替换本地 fallback）30 min
P3语音播放占位20 min
P3分享匹配卡20 min
顺序反了会出事

注意 P0 里是本地解析而不是 LLM。先保证离线能跑通全流程，再往上接模型。

07 / Acceptance

验收

演示能连续走通以下动作即算完成：

  1. 输入完整需求 → 得到高契合度搭子
  2. 只输入游戏名 → 仍能匹配
  3. 输入未收录的游戏 → 不报错，降级提示后仍给结果
  4. 连续换三个不同搭子，契合度递减合理
  5. 进入聊天，收到回复，拿到房间号
  6. 手机端和桌面端都能完整操作
  7. 全程无注册、无登录、无表单
  8. 断网状态下全流程仍可跑通
  9. 从进入到看到结果不超过 30 秒

08 / Out of Scope

明确不做

  • 真实用户系统
  • 真实在线匹配
  • 真实语音通话
  • 好友关系
  • 内容社区
  • 支付
  • 审核与信用系统
  • 原生 App
必须做的一件小事

结果卡上必须有「模拟玩家 · Demo 演示数据」字样。含糊处理会伤可信度，明确标注反而显得专业。

09 / Narrative

演示时要讲、但不做的三件事

01

复玩率是北极星。匹配只是漏斗入口，真正的产品是把匹配到的人沉淀成固定搭子。

02

商业化走订阅，不走陪玩抽成。抽成会引来供给侧职业化，「搭子」的平等感消失，还要背资金、纠纷和审核。

订阅的付费点应是优先匹配、更细筛选维度、固定搭子沉淀——不是把「只匹配认证真人」做成付费墙，安全应当免费。

03

最大的未验证假设：两个陌生人从匹配成功到真的一起开一局，中间这一跳的转化率。Demo 跳过了它，这是要坦白的。

10 / Risks

已知风险

01语音一旦成为核心，产品会迅速被「找女声」的需求淹没
Soul、比心、TT 语音都走过这条路。V0.1 只做播放占位，不作为匹配维度。
02陌生人 + 开麦，性别与骚扰绕不开
结果页保留一个举报 / 屏蔽入口（Demo 中只做交互反馈），不留会被追问。
03分享卡不带用户输入原文
只展示解析后的标签，避免带出隐私内容。
